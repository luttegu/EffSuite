Efficiency transfer and coincidence summing for HPGe detectors

An open-source desktop app and command line around Tim Vidmar's EFFTRAN 5.0, MEFFTRAN 1.9 and WEFFTRAN, for gamma spectrometry laboratories working with cylindrical, Marinelli and well geometries.

What EffSuite computes

It replaces Excel and VBA workbooks, keeps the verified Fortran physics, and records every input behind a result so it stays traceable.

Efficiency transfer to the sample geometry

Start from one efficiency curve measured with a calibration standard. For each energy, the engine computes the ratio of sample to standard efficiency in the same detector, so a sample with a different height, container, matrix or density gets its own calibration without a new standard. Each transferred value keeps the transfer uncertainty of the original programs.

.CAL .EFT .csv 2 to 93 points, exported as .CAL or .EFT

Summing factors in parallel

Cascade coincidence summing factors for every nuclide in the library, computed in one pass across separate worker processes instead of a serial workbook loop. Each factor carries its relative standard uncertainty u(C).

NIST XCOM cross-sections

XCOM 3.1 photon cross-sections built in. Define your own sample matrices and scale bulk density by ρ/ρ₀ for each sample.

2D cross-section drawings

An axial section of detector and sample, with dimension callouts placed so they never overlap, for cylindrical, Marinelli and well geometries.

Vendor files left intact

Original templates are never overwritten. Every exported calibration and library file is read back and checked right after it is written.

Command line for LIMS

Batch-process CSV matrices and replay GUI project files without a window, through EffSuite_CLI.exe or from Python.

Audited Fortran physics

Density scaling, full-precision transfer factors and the boundary of tall samples in well detectors, with every value passed to the engines in double precision. Departures from the originals are documented.

Genie 2000 and GammaVision

Read reference efficiency curves and write summing-corrected libraries for the two gamma spectrometry systems most laboratories run.

Canberra / Mirion

Genie 2000

Works through the CAM interface, with registered 32-bit and 64-bit type libraries.

  • .CALEfficiency transferred to the sample geometry, written as *_sample.CAL
  • .NLBEach line's abundance divided by its summing factor C, written as *_corrected.NLB
  • .CTFCertificate emission rates updated, written as *_corrected.CTF
  • Each copy is reopened through COM and checked before it is released

ORTEC

GammaVision

Pure Python, following Tim Vidmar's original gv.f routines and the EFFTRAN.EFT format. Nothing else to install on Windows.

  • .EFTReads both the 11-token EFFTRAN and the 5-token MEFFTRAN layout
  • .LIBReads and writes the 128-byte direct-access records of the EFFTRAN.Lib layout
  • _gv.txtA <name>_gv.txt report with energy, old and new yields, and factors
Testers wanted. GammaVision support was written from the EFFTRAN specification without access to GammaVision, so it has not been tested in a laboratory yet. If you run GammaVision, please report your results.

Command line and scripting

Call EffSuite from Python, C#, PowerShell or batch scripts.

This run transfers a calibration to a 55 mm water sample and writes the summing-corrected library on four workers. Every option is in the CLI integration guide.

EffSuite_CLI.exe cylinder \ --detector "High-energy" \ --standard "Solution" \ --sample "Water" \ --sample-height 55.0 \ --sample-density 1.000 \ --calibration "C:\Data\Standard.CAL" \ --library "C:\Data\LIBRARY.NLB" \ --output-cal "C:\Output\Sample.CAL" \ --output-nlb "C:\Output\Corrected.NLB" \ --workers 4
